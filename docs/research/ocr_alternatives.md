## 结论（5 条）

1. **版本新鲜度呈现明显两极**：RapidOCR（`rapidocr` 3.9.2，2026-07-21）与 Tesseract 引擎（5.5.3，2026-07-24）都在核查前约两个月内发布过新版本；CnOCR 2.3.3（2026-07-05）紧随其后；而 **EasyOCR 最新 release 停留在 2024-09-24 的 1.7.2**，2025-12-05 之后仅有一次 README 改动，版本线已约两年未推进。链接：https://github.com/RapidAI/RapidOCR/releases 、https://github.com/tesseract-ocr/tesseract/releases 、https://github.com/breezedeus/CnOCR/releases 、https://github.com/JaidedAI/EasyOCR/releases

2. **四者代码许可证均为 Apache-2.0，但「模型权重许可证」这一层只有 Tesseract 与 RapidOCR 有官方文字说明**：Tesseract 的 `tessdata` 仓库 README 明确「All data in the repository are licensed under the Apache-2.0 License」（chi_sim 在其内）；RapidOCR 英文 README 说明模型派生自 PaddleOCR、上游权重版权归百度、按 Apache-2.0 再分发，但**其引用的 `MODEL_LICENSES.md` 在仓库根目录不存在（404）**，故逐模型的来源/哈希无法确认。CnOCR 与 EasyOCR 的**权重许可在官方页面上未见明确条款 —— 不确定**；CnOCR 另有官方明示的「Pro 模型需购买 / 星球会员专享」模型，EasyOCR 官方页面未声明权重适用何种许可。链接：https://github.com/tesseract-ocr/tessdata/blob/main/README.md 、https://github.com/RapidAI/RapidOCR/blob/main/README.md 、https://github.com/breezedeus/CnOCR/blob/master/README.md 、https://github.com/JaidedAI/EasyOCR/blob/master/README.md

3. **四者都能给出坐标，但粒度不同，且只有两个能到「词/字」级**：RapidOCR 默认返回文本行 `boxes (N,4,2)` + `txts` + `scores`，开启 `return_word_box=True` 后 `word_results` 提供单字 4 点坐标；Tesseract 通过 hOCR / TSV 官方输出同时提供**行级与词级** bbox（`ocr_line` / `ocrx_word`、TSV `level=4` 行 / `level=5` 词），pytesseract 还可取字符级 `image_to_boxes`；CnOCR 的 `position` 为**行级** `(4,2)` 四点框；EasyOCR 的 `readtext` 返回**行/文本框级** 4 点多边形（`detect()` 另返回 `horizontal_list` / `free_list`）。**CnOCR 与 EasyOCR 官方均未见词级/单字级坐标字段 —— 不确定其是否具备该能力**。链接：https://github.com/RapidAI/RapidOCRDocs/blob/main/docs/install_usage/rapidocr/usage.md 、https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html 、https://github.com/breezedeus/CnOCR/blob/master/docs/usage.md 、https://www.jaided.ai/easyocr/documentation

4. **CPU 可行性上四者都可行，但「默认行为」差别很大**：Tesseract 是纯 CPU 引擎，官方无 GPU 依赖说明（官方 Benchmarks 亦在 CPU 上测试，并说明 5.0.1 起 OpenMP 默认关闭、建议 `OMP_THREAD_LIMIT=1`）；RapidOCR 官方文档直接**推荐先使用 ONNX Runtime CPU 版**；CnOCR 的 `context` 参数**默认为 `cpu`**，且识别/检测后端默认 `onnx`；而 **EasyOCR 的官方 API 文档写明 `gpu` 参数默认 `True`**，需要在构造 `Reader` 时显式传 `gpu=False` 才走 CPU-only（官方 release notes 说明 CPU 模式下默认启用动态量化）。链接：https://tesseract-ocr.github.io/tessdoc/Benchmarks.html 、https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/usage/ 、https://cnocr.readthedocs.io/zh-cn/stable/usage/ 、https://www.jaided.ai/easyocr/documentation

5. **中文效果「官方数据」仅在上游 PaddleOCR 侧存在；四个项目自身都没有中文准确率表**：RapidOCR 官方模型列表页无精度字段，其模型来自 PaddleOCR，上游官方页面给出 PP-OCRv6 检测 Hmean（medium 86.2% / small 84.1% / tiny 80.6%）与识别 Avg Accuracy（medium 83.2%），且官方注明 PP-OCRv6 指标基于内部多场景评估集、与 v5/v4 的通用评估集**不可直接对比**；CnOCR 官方模型表只有模型大小与支持语言，无准确率；EasyOCR 官方 README/release notes 无中文精度数字；Tesseract 官方 Benchmarks 只测速度、UNLV 测试是 1995 年英文测试。**因此「中文口碑」在四个项目自身官方页面上均无可靠数据支撑 —— 一律记为不确定**。链接：https://rapidai.github.io/RapidOCRDocs/main/model_list/ 、https://www.paddleocr.ai/latest/version3.x/pipeline_usage/OCR.html 、https://cnocr.readthedocs.io/zh-cn/stable/models/ 、https://github.com/JaidedAI/EasyOCR/blob/master/releasenotes.md 、https://tesseract-ocr.github.io/tessdoc/Benchmarks.html
